# UI/UXの実装・評価契約

本書は、2026年9月28日及び29日の UI/UX 改修（以下「本改修」といいます。）について、実装及び評価の契約を定めます。

## 1. 目的と責務

情報の読みやすさ及び正確さを優先します。既存の URL、認証並びに生成→確認→公開の流れを維持します。

`components/ui` は視覚部品を、業務画面は入力と表示を、`lib/planningTransport` は編集単位の通信と同一要求の再送を、`lib/planningRead` は中断可能な参照を、`lib/apiTarget` は共通の接続先を、それぞれ担当します。

法的な計算及び公開の判断は、既存のバックエンドの責務です。クライアント側に新しい計算を追加してはなりません。

ダッシュボードは、`GET /planning/dashboard?scope_id=…&period=YYYY-MM` を使います。

この API は、既存の publications 及び requests の認可済みの読取りから集計し、`role/visibility/observed_at/sources/metrics` を返します。

`metrics` は、値、available／unknown の別及び理由からなります。取得できない値は null であり、0 ではありません。公開期間の件数と本人の勤務件数とを区別します。

稼働率、健康影響及び法令適合率は算定していません。見本データの使用は、Storybook に限ります。

## 2. 状態と処理の流れ

```mermaid
flowchart LR
  U[部署・対象月・本人の操作] --> R[中断可能な認可付き読取り]
  R --> A[planning/dashboard API]
  A --> P[正本の公開版・申請]
  P --> V[値・不明・参照版の表示]
  U --> E[業務編集セッション]
  E --> T[本文・期待版・冪等キー]
  T --> G[既存APIの認可・検証・トランザクション]
  G --> C[確定結果の再取得]
```

```mermaid
stateDiagram-v2
  [*] --> 読込中
  読込中 --> 表示済み: 権限付き応答
  読込中 --> 取得失敗: 認証・認可・通信・サービス障害
  取得失敗 --> 読込中: 明示的な再試行
  表示済み --> 編集中
  編集中 --> 競合: 409
  競合 --> 編集中: 三者差分の明示確認
  編集中 --> 応答不明: 通信断
  応答不明 --> 表示済み: 同じ本文・キーで結果照会又は再送
  編集中 --> 検証待ち: 保存
  検証待ち --> 公開確認: 現在版の検証通過
  公開確認 --> 表示済み: 既存公開APIで確定
```

消去、復元及び休暇の状態機械は、既存のドメイン実装及び監査台帳を正本とします。監査台帳は、公開範囲外に保管しています。この図だけをもって、全遷移を検証済みとはしません。

ER 図では、ORM の生成物と実際の PostgreSQL の観測とを区別します。アプリ、制御及び世代照合（witness）の図は別々に保存し、サービス間の参照及び JSON 内の参照を物理的な外部キー（FK）に見せません。`devtools.er.physical --database-env <変数名> --label app|control|witness --output <新規場所>` は、読取り専用です。

公開、休暇、消去及び復元の個別の図は、[業務状態の対応](../architecture/er/workflow-states.md)を参照してください。

## 3. 採用根拠と反証

| 根拠 | 適用 | 限界 |
|---|---|---|
| DADS（参考文献1） | 16px を基本とし、説明と比較表の密度を分けます | 文字サイズの万人共通の最適値ではありません |
| Piepenbrock 2013（参考文献2） | 既定は明るい配色とし、選択肢は保持します | ドイツ語の視力・校正課題です。日本語の勤務編成又は視覚障害全般への直接の証明ではありません |
| JAMIA の模擬 EHR 比較（参考文献3） | 関連情報を近くに配置します | 研修医51人の限定された課題です。効果量を本アプリへ移しません |
| WCAG 2.2（参考文献4） | AA を基準とし、一連の業務を評価します | 独自の検査は全適合の証明ではありません。ターゲットサイズ等の例外と AAA とを区別します |
| 個人情報保護委員会（PPC）の通則編（参考文献8） | 目的の限定、権限、合成データ、保存の抑止 | 配色又は DB 構造を法律が指定しているわけではありません |
| Playwright（参考文献9） | 同一のブラウザ、OS 及びフォントで比較します | 環境差と機能不良とを区別します |

## 4. 受入と利用者評価

既存の操作台帳を基準に、役割×操作×（正常／空／大量／処理中／エラー／409／未保存／再送）を対応付けます。

新しいテストが一部で成功しても、未接続の行を成功に変えてはなりません。光学検査の打切り及び判定不能も、未完了として扱います。

画像は1枚ずつ、文字の欠落、主操作、状態の誤認、長文、折返し及びフォーカスを確認します。重要な領域をマスクしてはなりません。

API の実通信は、メソッド、パス及び状態だけを記録し、認証情報及び本文を収集しません。静的な経路の推測は、未確認の候補です。

実際の拡大（200%・400%）、キーボードだけでの操作の完結、実機の Safari 及び VoiceOver による確認、並びに実際の職員による評価は、自動検査とは別の受入です。

初回は、3役割について各3人で問題を発見する評価とします。確認のための評価は AB/BA で釣り合わせ、同じ難度の別の課題を使います。

主要な指標は、正しい完了、重大な誤操作及び時間です。予備評価における参加者単位の対数時間差の標準偏差を s とします。

両側5%、検出力80%で10%の短縮を検出するための人数の近似は、`ceil(((1.959964+0.841621)*s/log(0.9))^2)` とします。

人数は最低24人とし、役割ごとに AB/BA が同数になるよう6の倍数へ切り上げます。実施の前に、脱落の見込み及び小標本での近似の妥当性を再確認します。

10%は製品の目標であり、規格又は法的な閾値ではありません。反復した課題を独立した参加者として数えず、参加者単位の95%区間を示します。

失敗、中断及び欠測を保持します。重大な誤操作は、修正の対象とします。観測が0件であることは、母集団での危険がゼロであることを意味しません（参考文献15）。

参加者が確保できない場合又は精度が不足する場合は、有用性又は最適性を確定しません。過去の内部評価の記録は個別の作業環境を含むため、公開候補には収録しません。公開用の評価票は、`docs/ideal-ui/evaluation/` に置きます。

本改修の UI の結果を、25か月故障、全辺 API、1,200件性能及び施設受入の合格へ流用してはなりません。

## 6. 描画証拠の読み方

2026年9月28日のビルドは macOS の隔離した作業コピーで作成し、3種類のブラウザは固定した Linux のイメージで描画します。

Linux でのクリーンな配布ビルドを実施したとは記載しません。ビルド成果物、配布フォント及び検査ソースは、ハッシュで固定します。

合成 API の観測時刻及びブラウザの時計は、2026-09-28T00:00:00Z に固定します。ただし、業務の法的な計算の時刻及びワーカーの処理時間は変更しません。観測時刻の差替えは、模擬認証（mock）を使う development 環境の隔離 ASGI ファクトリに限り許します。

フォーカスの到達検査は、通常の文書又は表示中の modal dialog／alertdialog を範囲とします。この検査では、一時的な終端要素まで移動できたこと、及び可視の対象で未到達のものがゼロであることを確認します。

モーダルが背景へ Tab を出さないこと自体は、失敗ではありません。内部の不正なトラップ、打切り及び対象の漏れは、未完了とします。

終端要素は、検査の後に除去します。Escape、背景の inert 及び開いた要素への復帰は、別の操作テストで確認します。

この補助的な検査は、全キーボード経路又は支援技術の証明ではありません。

## 7. 全画面の情報設計（IA）

本改修で追加した `devtools/visual/build.mjs --linux` は、既存の固定イメージで Linux のビルドを作ります。

ブラウザも、固定した Linux のイメージで動かします。現行の HTTPS 配信プロセスは macOS の Node であり、全サービスの Linux での稼働とは区別します。

画像比較は、改修前のソースからも同じ Linux のビルドを作った別の系列に限ります。

主導線は、`lib/navigation.ts` のダッシュボード／勤務表・計画／業務管理／施設設定です。

旧 `/schedule` 及び `/requests` は URL を保持し、業務一覧の「互換管理」に配置します。

公開勤務と旧保存記録、年休の請求・予約・実取得・義務、並びに人物制御と全コピーの消去を、それぞれ混同しません。

業務ページは、目的・対象 → 選択 → 詳細・根拠 → 許可された操作 → 結果 の順とします。

契約及び実績は、広い幅では一覧と詳細を並べて表示し、狭い幅では同じフォームを縦に表示します。

別画面の実装又は複製した法的な計算を作りません。主要な業務への画面内のリンクはアンマウントせず、三者差分、未保存の値及び冪等キーを保持します。破壊的な操作は、既存の確認及び権限制御を通ります。

旧休暇枠はグローバルな役割で判定し、LEADER は参照だけ、ADMIN 及び DEVELOPER は既存 API の更新範囲とします。

業務ページは部署所属の役割で判定し、DEVELOPER を部署の ADMIN へ変換しません。

表示用の Cookie 及びリンクは、認可の証拠ではありません。最終的な判定は、API が行います。

```mermaid
flowchart TB
  main[主導線] --> dashboard[ダッシュボード]
  main --> planning[勤務表・計画]
  main --> workflows[業務管理]
  main --> settings[施設設定]
  workflows --> work[契約 / 兼業 / 休暇 / 実績 / 個人情報 / 復旧]
  workflows --> legacy[互換管理]
  legacy --> saved[旧保存シフト /schedule]
  legacy --> quota[旧休暇枠 /requests]
  work --> candidate[許可対象と現在版]
  candidate --> edit[既存専用フォーム]
  edit --> api[認可・期待版・冪等キーを検査する既存API]
  api --> result[確定結果 / 未確認 / 競合 / 残存]
```

操作及びルートの正本は、既存の統合受入（2026年9月23日）の操作台帳です。この操作台帳は監査台帳の一部であり、公開範囲外に保管しています。

42操作の結果を上書きせず、`screen` 及び `additional_surfaces` の対応を同じ操作台帳へ追加しました。

全状態の実行を確認していない行は、`acceptance_pending` のままとします。

### 7.1 根拠と適用範囲

- DADS タイポグラフィ（参考文献1）：本文16px を基本とし、比較表の密度は用途別とします。万人共通の最適値ではありません。
- JAMIA 2021（参考文献3）：模擬 EHR における問題別の情報の集約です。勤務表へ効果量を外挿しません。
- PeerJ 2019（参考文献13）：331人の課題で、外観と時間・正確さの改善とは一致しませんでした（確認した範囲は著者抄録）。有意差がないことを、効果がないことの証明としません。
- WCAG 2.2（参考文献4）：完全な手続、リフローにおける二次元の表の例外、並びに AA と AAA とを区別します。自動評価の限界（参考文献7）を保持します。
- 個人情報保護委員会の通則編（参考文献8）：利用目的、安全管理及びアクセス制御と照合します。特定の UI を法定の方式としません。
- 厚生労働省の年5日管理の資料（参考文献14）：半日と時間単位の年休の意味を混同しません。UI に法的な計算を再実装しません。

実際の職員による有用性の評価は、未実施です。各役割3人での問題発見と、AB/BA の比較評価とは、別の段階とします。

反復した課題を独立した参加者として数えず、失敗、中断及び欠測を保持します。

最低24人は運用上の下限であり、精度又は検出力を保証する人数ではありません。

観測がゼロの誤操作についても、母集団での危険がゼロとはしません（NIST の比率推定、参考文献15）。

### 7.2 本改修の実装の判断と反証

- セクションの切替えには、初期状態では文書内のリンクを採用しました。フォームを非表示にし、又は再生成するタブを増やすと、未保存の値や再送のキーを失う可能性があるため、既存の編集セッションを維持します。スクロールの距離が最適であるかは、未評価です。
- 明示された別部署へのリンクは、現在の部署で上書きしません。部署及び期間は表示の文脈であり、許可の根拠ではありません。操作の範囲は、API から返る所属及び権限が決めます。
- 旧休暇枠は、現行の年休の計算から分離します。取得の失敗時及び読込みの途中には、残数ゼロを示しません。応答の順序が逆になっても、以前の月の値を現在の月に表示しません。
- 密な比較表は必要な最小幅を維持し、説明付きの、キーボードで操作できる横スクロール領域にします。WCAG の二次元の表の例外は、狭い幅で見出しを一文字ずつ改行することを推奨する根拠ではありません。
- 画像の重なり検査が成功しても、説明内容の誤り及び関連情報の離隔は検出できません。本改修でそれらが独立したレビューで見つかった事実を、自動検査の限界として記録します。

## 8. 本人・権限・状態の意味契約

本人欄は、`GET /auth/me` の表示名及び識別子を使用します。local の識別子は「ログインID」、OIDC のアプリ内識別子は「アカウントID」とします。表示名が欠損している場合は「表示名未登録」とし、権限名又は認証状態を名前として補完しません。display Cookie は、表示及び認可の正本にしません。

全体の権限、部署所属の権限及び本人との関係は、別の概念です。部署の ADMIN は「部署管理者」、LEADER は「部署責任者」、STAFF／PHARMACIST は「部署職員」とします。

旧来のスコープなしの API に限り、`/auth/legacy-context` が単一の所属を person_id／effective_role へ対応付けます。複数の所属は、従来どおり拒否します。この拒否を、アカウントの本人確認の失敗として表示しません。

本人確認の読取りは、セッションを更新しません。確認中及び確認不能の間は、業務内容を保持したまま非表示とし、操作できないようにします。認証の終了又はアカウントの変更では、旧業務を破棄します。署名、失効及び制御サービスの検査は、API 側に残します。

年休取得義務の `fulfilled`、`overdue` 及び `at_risk` は、API の結果を翻訳するだけとし、未知の値を正常又は不足見込みへ補完しません。期間、半日単位からの日数表示及び付与主体は、別の項目として保持します。

既存の操作台帳の `semantic_audit` は、概念、正本、対象、時点版、単位、状態、許可操作及びテストを照合するための欄です。本人表示の成功を、その操作の全業務意味の受入へ読み替えません。

年間区分期間の同意は、状態、資料名、確認責任者及び時差付きの期限を別々の入力にします。文字列の区切り又は空白を正規化して、証拠の本文を変更しません。日数及び時間量は整数で保持し、三者差分には各期間の資料と期限まで表示します。UI の構造検査は、法的な公開可否の再計算ではありません。
