# 認知中心UI v3 独立レビュー

本書は、認知中心UI v3 の実装に対して行った独立レビューについて、範囲、指摘、対応及び残る判定条件を記録します。

## 1. 範囲と方法

実装担当とは別の AI によるレビュー担当が、独立したレビューとして、基点 `3bf57dec` からの全差分、要件、構造テスト、生成した契約、画面と API の境界、E2E テスト及び検証報告を静的に確認しました。レビュー担当者は、ファイルを変更していません。本レビューは作成者から独立したコードレビューですが、計画が求める別の人による本番採用レビューの代替ではありません。

## 2. 指摘と対応

| 重要度 | 指摘 | 対応 |
|---|---|---|
| 高 | URL 上の期間・公開版・ケース・職員が、本文の選択へ反映されません | `workspaceSelection.ts` で、形式と、所属する対象範囲（scope）内の公開版であることとを検証し、サーバー側・クライアント側の初期化から各用途画面へ渡しました。不正な値や不一致を、黙って別の対象へ置き換えません。 |
| 高 | Storybook と API に接続する画面が、別の実装です | Storybook でも `WorkspaceShell`、`WorkspaceContent`、用途別画面及び `LiveApi` を使用し、差し替えるのは合成の fetch 応答だけにしました。`SyntheticPurposeView` は、実行経路及びストーリーから参照されません。 |
| 高 | U01〜U27 が到達の確認だけであり、U25 の実消去及び U26 の復旧演習を含みません | U01〜U27 を、変更操作まで行う系列へ置き換えました。U25 は、専用の合成人物を実際に消去し、残存0件及び再導入の拒否を証跡に残します。U26 の復元そのものは、Web UI から分離した隔離 PostgreSQL での運用演習で検証します。 |
| 中 | 許可された役割・画面経路の一部しか光学監査しません | `usecases.json` から、許可された役割・画面経路のストーリー52件を生成し、3エンジン・3幅・4配色の監査対象にしました。 |
| 中 | `usecases.json` と、実行時のルート・役割の定義とが二重になっています | ルート、役割、Storybook ID 及び E2E ID を生成し、`views.ts` とナビゲーションは生成物を直接利用します。生成物の更新漏れ及び参照漏れのテストを追加しました。 |
| 中 | 補助 API の1件が失敗すると、作業画面（workspace）全体が空になります | 認証、対象範囲及び公開版を必須の境界とし、勤務表、集計、当日運用、安定性、通知等は独立した結果として保持します。部分的に失敗した場合は、取得済みの情報を残し、失敗を明示します。 |
| 中 | ZIP を証跡なしで生成でき、未コミットの状態を再現できません | ギャラリー、検証マニフェスト及び検証用の資産を必須とし、追跡・未追跡・削除の全ての状態の SHA-256 を照合します。生成時刻を固定し、実行環境及び未完了の判定条件を収録します。 |
| 中 | 利用者メニューと従来のセッション操作が、二重に表示されます | 作業画面では従来のナビゲーションを表示せず、利用者メニューに外観、個人設定、通知及びサインアウトを統合しました。セッション期限の警告及び失効の処理だけは、全画面に共通の安全制御として維持しました。 |

## 3. 再確認

最終の再レビューの結果は、高0件、中0件、低1件でした。U01〜U27 は243/243件、機能フラグ `IDEAL_UI` の既定値（無効）での既存機能は267/267件、役割・画面経路の光学監査は156/156件、状態の監査は150/150件が、いずれも再試行なしで成功しました。焦点を絞った再確認では、pytest 45件、並びに Jest 7スイート・75テストが成功しました。全体の検証の内訳は、[verification.md](verification.md) 及び ZIP 内の機械可読な検証証跡を正本とします。準備段階で失敗した実行及び修正前の結果は、合格の件数に加えません。

残る低重要度の指摘は、匿名の監査タイムラインが操作主体の現在の役割を求める際に、無効化済みの所属を除外していない点です。この役割は、氏名・職員IDの開示及び認可の判断には用いておらず、影響は管理者向けの表示の精度に限られます。公開条件である「高・中0件」は満たします。今後、`AccountMembership.active` を条件に加え、無効な所属だけを持つ主体では役割を表示しないことを確かめる反証テストを追加します。この未修正の事項を、本番採用の安全性が確認済みであることの根拠には用いません。

## 4. 残る独立した判定条件

- 別の人によるセキュリティ及び業務上の妥当性のレビュー
- 30名による AB/BA の利用者評価
- VoiceOver/NVDA の実機評価
- 対象環境での200%・400%拡大、強制色及び人による光学確認
- 実運用に相当する p75 の Core Web Vitals

これらの判定条件が未完了であるため、本レビューだけで「使いやすい」「WCAG適合」「臨床安全性を証明済み」とは結論しません。機能フラグ `IDEAL_UI` の本番での既定値は、無効のままとします。
