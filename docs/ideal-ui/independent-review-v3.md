# 新画面（認知中心UI v3）第三者的レビュー

## 範囲と方法

実装担当とは別のAIレビュー担当が、新画面（開発名：認知中心UI v3）を対象として、基点`3bf57dec`からの全差分、要件、構造試験、生成契約、画面とAPIの境界、E2E及び検証報告を静的に確認した。レビュー担当は、ファイルを変更していない。本レビューは、別担当によるコードレビューではあるものの、計画が要求する「別の人」による本番採用レビューの代替ではない。

## 指摘と対応

| 重要度 | 指摘 | 対応 |
|---|---|---|
| 高 | URL上の期間、公開版、ケース及び職員が、本文の選択へ反映されない | `workspaceSelection.ts`において、形式及び所属する施設・部署の範囲内の公開版であることを検証し、サーバー側及びクライアント側の初期化から各用途別画面へ渡した。不正な値又は不一致は、通知なしに他の対象へ置換しない。 |
| 高 | StorybookとAPIに接続する画面とが別個の実装である | Storybookにおいても、`WorkspaceShell`、`WorkspaceContent`、用途別画面及び`LiveApi`を使用し、差し替える対象は合成したfetch応答のみとした。実行経路及びストーリーは、`SyntheticPurposeView`を参照しない。 |
| 高 | U01〜U27が到達確認のみであり、U25の実際の消去及びU26の復旧演習を含まない | U01〜U27を、変更操作まで実行するdeepの業務シナリオへ置換した。U25においては、専用の架空の人物（合成データ）を実際に消去し、残存0件及び再導入の拒否を検証記録として保持する。U26の復元そのものはWeb UIから分離し、隔離したPostgreSQLにおける運用演習により検証する。 |
| 中 | 許可された役割と画面経路の組合せの一部しか、視覚的検査の対象としていない | `usecases.json`から、許可された役割と画面経路の組合せのストーリー52件を生成し、3エンジン・3画面幅・4配色の検査対象とした。 |
| 中 | `usecases.json`と、実行時のルート及び役割の定義とが重複している | ルート、役割、Storybook ID及びE2E IDを生成し、`views.ts`及びナビゲーションは生成物を直接利用する。さらに、最新性の検査及び参照漏れの試験を追加した。 |
| 中 | 補助APIが1件失敗した場合、新画面全体が空になる | 認証、施設・部署の範囲及び公開版を、必須の境界とする。勤務表、集計、当日運用、安定性、通知等は、各々独立した結果として保持する。部分的な失敗の場合は、取得済みの情報を保持し、失敗を明示する。 |
| 中 | 検証記録なしでZIPを生成でき、未コミットの状態を再現できない | ギャラリー、検証の目録（verification manifest）及び検証資料（verification assets）を必須とした。追跡対象、未追跡及び削除の全ての状態について、SHA-256を照合する。また、生成時刻を固定し、実行環境及び未完了の判定基準を収録する。 |
| 中 | 利用者メニューと従来のセッション操作とが二重に表示される | 新画面においては、従来のナビゲーションを表示しない。外観、個人設定、通知及びサインアウトは、利用者メニューへ統合した。ただし、セッション期限の警告及び失効の処理のみは、全画面に共通の安全制御として維持した。 |

## 再確認

最終の再レビューの結果は、高0件、中0件、低1件であった。U01〜U27は243/243件、機能フラグ無効時の試験は267/267件、役割と画面経路の組合せの視覚的検査は156/156件、状態の検査は150/150件が、いずれも再試行なしで成功した。対象を限定した再確認においては、pytest 45件並びにJest 7スイート及び75試験が成功した。全体の検証の内訳は、`verification.md`及びZIP内の機械可読な検証記録を原本とする。準備に失敗した実行及び修正前の結果は、合格件数には算入しない。

残存する低重要度の指摘は、匿名の監査タイムラインが操作主体の現在の役割を導出する際に、無効化済みの所属を除外していない点である。この役割は、氏名及び職員IDの開示並びに認可の判断には用いておらず、影響は管理者向けの表示の精度に限られる。公開条件である高・中0件は満たす。今後、`AccountMembership.active`を条件に追加する。併せて、無効な所属のみを有する主体においては役割を表示しないことを確認する異常系試験を追加する。この未修正の事項を、本番採用の安全性が確認済みであることの根拠には用いない。

## 残る独立した判定基準

- 別の人によるセキュリティ及び業務妥当性のレビュー
- 30名のAB/BAユーザビリティ評価
- VoiceOver/NVDAの実機による評価
- 対象環境における200%・400%拡大、強制色及び人による視覚的検査
- 実運用相当の環境におけるCore Web Vitalsの75パーセンタイル

これらが未完了であることから、本レビューのみをもって「使いやすい」「WCAG 2.2に適合」「臨床安全性を証明済み」とは結論しない。`IDEAL_UI`の本番における既定値は無効（OFF）のまま据え置く。
