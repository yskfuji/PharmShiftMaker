# 認知中心UI v3 独立レビュー

## 範囲と方法

実装担当とは別のAIレビュー担当が、基点 `3bf57dec` からの全差分、要件、構造試験、生成契約、画面/API境界、E2Eと検証報告を静的に確認した。レビュー担当はファイルを変更していない。これは別担当によるコードレビューではあるが、計画が要求する「別の人」による本番採用レビューの代替ではない。

## 指摘と対応

| 重要度 | 指摘 | 対応 |
|---|---|---|
| 高 | URL上の期間・公開版・ケース・職員が本文の選択へ反映されない | `workspaceSelection.ts`で形式と所属scope内の公開版を検証し、server/client初期化から各用途画面へ渡した。不正値や不一致は黙って別対象へ置換しない。 |
| 高 | StorybookとAPI接続画面が別実装 | Storybookも`WorkspaceShell`、`WorkspaceContent`、用途別画面と`LiveApi`を使用し、差し替えるのは合成fetch応答だけにした。`SyntheticPurposeView`は実行経路・物語から参照されない。 |
| 高 | U01〜U27が到達確認だけで、U25実消去・U26復旧演習を含まない | U01〜U27を変更操作まで行うdeep系列へ置換した。U25は専用合成人物を実消去して残存0・再導入拒否を証跡化し、U26の復元そのものはWeb UIから分離した隔離PostgreSQL運用ドリルで検証する。 |
| 中 | 許可されたrole-routeの一部しか光学監査しない | `usecases.json`から52の許可role-route物語を生成し、3エンジン・3幅・4配色の監査対象にした。 |
| 中 | `usecases.json`と実行時ルート・役割定義が二重化 | ルート、role、Storybook ID、E2E IDを生成し、`views.ts`とナビゲーションは生成物を直接利用する。freshness/参照漏れ試験を追加した。 |
| 中 | 補助API一件の失敗でworkspace全体が空になる | 認証・scope・公開版を必須境界とし、勤務表、集計、当日運用、安定性、通知等は独立結果として保持する。部分失敗は取得済み情報を残して明示する。 |
| 中 | ZIPを証跡なしで生成でき、未コミット状態を再現できない | gallery、verification manifest、verification assetsを必須化し、全追跡・未追跡・削除状態のSHA-256を照合する。生成時刻を固定し、実行環境と未完了ゲートを収録する。 |
| 中 | 利用者メニューと従来のセッション操作が二重表示 | workspaceでは従来ナビを表示せず、利用者メニューへ外観、個人設定、通知、サインアウトを統合した。セッション期限警告・失効処理だけは全画面共通の安全制御として維持した。 |

## 再確認

最終再レビューの結果は、高0件、中0件、低1件であった。U01〜U27は243/243件、旗OFFは267/267件、role-route光学監査は156/156件、状態監査は150/150件が、いずれも再試行なしで成功した。焦点を絞った再確認ではpytest 45件、Jest 7 suites・75 testsが成功した。全体検証の内訳は `verification.md` とZIP内の機械可読な検証証跡を正本とし、失敗した準備実行や修正前の結果は合格件数に加えない。

残る低重要度の指摘は、匿名監査タイムラインが操作主体の現在の役割を求める際に、無効化済み所属を除外していない点である。氏名・職員IDの開示及び認可判断には用いておらず、影響は管理者向け表示の精度に限られる。公開条件である高・中0件は満たすが、今後 `AccountMembership.active` を条件に加え、無効な所属だけを持つ主体では役割を表示しない反証試験を追加する。この未修正事項を、本番採用の安全性が確認済みであるとの根拠には用いない。

## 残る独立ゲート

- 別の人によるセキュリティ・業務妥当性レビュー
- 30名のAB/BA利用者評価
- VoiceOver/NVDA実機評価
- 対象環境での200%・400%拡大、強制色、人間による光学確認
- 実運用相当のp75 Core Web Vitals

これらが未完了のため、本レビューだけで「使いやすい」「WCAG適合」「臨床安全性を証明済み」とは結論しない。`IDEAL_UI`の本番既定値はOFFのままとする。
