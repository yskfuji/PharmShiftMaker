## 3. 実行の経緯と範囲

### 3.1 U01〜U27 の実行

受け入れた U01〜U27 の行列は、各ケースにつき初回実行をちょうど1回記録します。親の実行器は、自ら作成したスキーマに限って検証し、削除しました。

これに先立つ診断用の実行では、242/243件が完了しました。完了しなかった1件では、WebKit の320pxで、テスト用の補助関数が1 ms 間隔で送った日本語1文字が欠落しました。この実行は失敗として保持し、合格には数えません。補助関数を、フォーカスの確定を伴う意図的な15 ms 間隔のキーボード入力1回へ変更した後、243件の行列全体を改めて開始し、再試行なしで合格しました。

U25 は、エンジン及び幅ごとに、消去の受領記録を追加で記録します。U26 は、意図して復元の実行を Web UI の外に置いています。別の運用演習が、記載した合成データの範囲で、バックアップからの復元、アクセス制限、消去の再適用及び復活しないことを確認します。

### 3.2 役割・画面経路の監査

役割・画面経路の監査は、作業画面（workspace）と同じ生成済みのルート契約及び本番の機能部品を用います。完了した1回の実行は156件の Playwright テストから成ります。各テストは12条件（ライト、ダーク、システム設定のライト及びシステム設定のダークを、320、768及び1440pxで）を実行します。別に作成したギャラリーはレビューの補助です。当該ギャラリーは、追加のブラウザ行列ではなく、支援技術及び人によるレビューの代わりにもなりません。

### 3.3 実行入力の凍結

ビルド、U01〜U27 の実行及び光学監査は、それぞれ実行に用いる入力を凍結し、ソース及びビルドのハッシュを記録しました。最終の本番ビルド及び光学監査の後に変更したソースは、3.1 で述べた E2E テストのキーボード用補助関数だけです。アプリケーション、描画及びビルドの入力は、バイト単位で同一のままでした。準備に失敗した実行及び修正前の実行は、パッケージの外に保持しますが、合格には数えません。
