# 新画面（認知中心UI v3） — 設計判断、限界及び反対の根拠、検証の範囲

## 結論

新画面（開発名：認知中心UI v3）においては、v2の真珠色、深藍、青緑及び抑制した琥珀色並びに自己ホストしたNoto Sans JPを維持し、情報設計のみを再構築する。画面の美観は、業務成績の代理指標としない。また、判断材料を同一の作業面に保持しつつ、日常の入口、工程及び長期タスクを区別する。

実装上の結論は、次のとおりである。

- 左ナビゲーション、ページ内ナビゲーション及び本文の3階層を固定する。背景、主作業面及び補助面の3つを超える視覚階層は設けない。
- 計画は、同一の情報に対する観点の切替えではないことから、タブとはせず、番号、短い到達条件及び現在位置を備える工程ナビゲーションとする。
- 申請、職員、ガバナンス及び設定においては、一覧及び現在の状態を先に示す。新規作成及び変更のフォームは、利用者が明示的に開く。
- 月間勤務表は、比較に適した意味的な表（table）を維持し、狭い画面幅においては、同一のデータの日別アジェンダを用いる。
- 施設・部署の範囲、期間、公開版及び検証状態は、全画面において同一の位置に配置する。公開、承認、消去及び無効化においては、対象、版、変更結果及び通知先を、操作の直前にも示す。
- URLは、列挙済みのルートに限って生成し、任意の戻り先URLは受け取らない。権限は、画面上で非表示にすることによってではなく、APIにより再検査する。

## 根拠、限界及び反対の根拠

| 判断 | 根拠 | 限界及び反対の根拠 | 実装及び測定 |
|---|---|---|---|
| タブと工程とを区別する | [デジタル庁・タブ](https://design.digital.go.jp/dads/components/tab/)は、同一主題に対する観点の切替えと手順とを区別している | 公開サイト向けの指針であり、薬剤部の計画業務における完了率を直接に示すものではない | 計画は工程ナビゲーション、申請等はページ内ナビゲーションとする。ユーザビリティ評価において、戻り、飛び越し及び誤公開を測定する |
| 一貫した階層及び用語を用いる | [W3C COGA](https://www.w3.org/TR/coga-usable/)及び[Consistent Navigation](https://www.w3.org/WAI/WCAG22/Understanding/consistent-navigation) | 一貫性のみでは、認知面のアクセシビリティ又はWCAGへの適合は証明できない | h1、施設・部署の範囲、期間、版及び次の操作を、固定位置に配置する。理解の確認及びVoiceOver/NVDAによる確認は、別途実施する |
| 表及び日別表示を併設する | [DADSデータテーブル](https://design.digital.go.jp/dads/components/table/accessibility/)及び[WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 代替表示が同一の意味を保持するか否かは、実データによる検証を要する | デスクトップ用の表及びモバイル用のアジェンダを、同一のモデルから生成する。両端、400%及び320 pxを検査する |
| 視覚的複雑性を抑制する | [CHI 2020](https://doi.org/10.1145/3313831.3376849)は、視覚的複雑性と検索及び記憶との関係を報告している | 単純化が行き過ぎた場合、資格、休息、版等の安全上必要な情報を隠す | 一覧においては優先度を絞り、最終判断の面には全ての根拠を保持する。検索時間及び誤判断を測定する |
| ダッシュボードの効果を一般化しない | [2026 umbrella review](https://pubmed.ncbi.nlm.nih.gov/41788668/)及び[patient-safety dashboard review](https://pmc.ncbi.nlm.nih.gov/articles/PMC8496385/) | 研究は不均質であり、データ品質、統合及び利用者による評価に不足がある | 「健康改善」「安全性向上」を主張しない。合成課題の完了、誤操作及び負荷のみを報告する |
| 美観と操作性とを区別する | [Tuch et al.](https://doi.org/10.1016/j.chb.2012.03.024) | 知覚による評価と実際の作業とは一致しない | VisAWI-Sと、完了率、所要時間、主観的作業難易度（Single Ease Question：SEQ）及びNASA-TLXとを、別個に解析する |
| Server Componentの境界を小さくする | [Next.js production checklist](https://nextjs.org/docs/app/guides/production-checklist) | フレームワークの構成は、業務領域における安全性を証明するものではない | 共通シェル、認証、施設・部署の範囲及び主要集計の初期の文脈はサーバー側で、変更操作及び操作後の用途別の再読取りはクライアント側で処理する。個人別の読取りはno-storeとし、APIにおける認可を維持する |

## 認知面及び視覚面の検査の判定

自動検査においては、切れ、重なり、横方向のあふれ、実効コントラスト、フォーカスの遮蔽、target size、文字間隔、強制色及びaxeについて、問題を検出する。この結果は、問題が検出されなかった条件の記録であって、WCAGへの適合の認定ではない。人による390/1024/1920 px、200%・400%、VoiceOver/NVDA及びキーボードのみによる確認は、別個の判定基準とする。

30名の評価は、役割別に10名とし、v2/v3をAB/BAの順序で各5名に割り当てる。採用条件は、重大な誤確定0件、重大な課題9/10以上、SEQの中央値5/7以上、完了者の減少1名以内及び所要時間の中央値の悪化15%以内とする。ただし、0/30は、母集団におけるリスクがゼロであることを意味するものではない。割合はWilson法の95%信頼区間により、対応のある差はブートストラップ法による区間により示す。二値の差はMcNemarの正確検定により、必要な多重比較はHolm法により示す。

## 現時点で主張しないこと

人による評価、実機による読み上げ、手動による拡大及び実運用環境におけるCore Web Vitalsの75パーセンタイルの各評価が完了するまで、「美しい」「使いやすい」「WCAG 2.2に適合」「臨床安全性を証明」「健康・離職を改善」と一般化しない。`IDEAL_UI`の本番における既定値は無効（OFF）のまま据え置く。
