# 認知中心UI v3 — 設計判断・反証・検証境界

## 結論

v3 は、v2 の真珠色・深藍・青緑・抑制した琥珀色と自己ホスト Noto Sans JP を保ち、情報設計だけを作り直す。画面の美観は業務成績の代理指標にせず、判断材料を同じ作業面へ残しながら、日常の入口、工程、長期タスクを区別する。

実装上の結論は次のとおり。

- 左ナビ、ページ内ナビ、本文の三階層を固定し、背景・主作業面・補助面の三つを超える視覚階層を作らない。
- 計画は同一情報の観点切替ではないためタブにせず、番号・短い到達条件・現在位置を持つ工程ナビにする。
- 申請・職員・ガバナンス・設定は、一覧と現在状態を先に示し、新規作成・変更フォームは利用者が明示的に開く。
- 月間勤務表は比較に適した意味的tableを維持し、狭幅では同じデータの日別アジェンダを用いる。
- scope、期間、公開版、検証状態は全画面で同じ位置に置く。公開・承認・消去・無効化では、対象・版・変更結果・通知先を操作直前にも示す。
- URLは列挙済みrouteだけを生成し、任意の戻り先URLを受け取らない。権限は画面非表示ではなくAPIで再検査する。

## 根拠と反証

| 判断 | 根拠 | 反証・限界 | 実装・測定 |
|---|---|---|---|
| タブと工程を分ける | [デジタル庁・タブ](https://design.digital.go.jp/dads/components/tab/) は同一主題の観点切替と手順を区別する | 公開サイト向け指針であり、薬剤部計画の完遂率を直接示さない | 計画は工程ナビ、申請等はページ内ナビ。利用者試験で戻り・飛び越し・誤公開を測る |
| 一貫した階層と言葉を使う | [W3C COGA](https://www.w3.org/TR/coga-usable/) と [Consistent Navigation](https://www.w3.org/WAI/WCAG22/Understanding/consistent-navigation) | 一貫性だけで認知アクセシビリティやWCAG適合は証明できない | h1、scope、期間、版、次の操作を固定位置にし、理解確認とVO/NVDAを別に行う |
| 表と日別表示を併設する | [DADSデータテーブル](https://design.digital.go.jp/dads/components/table/accessibility/) と [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 代替表示が同じ意味を保つかは実データで検証が要る | desktop tableとmobile agendaを同一モデルから生成し、両端・400%・320pxを監査する |
| 視覚的複雑性を抑える | [CHI 2020](https://doi.org/10.1145/3313831.3376849) は視覚的複雑性と検索・記憶の関係を報告する | 単純化しすぎると資格・休息・版など安全上必要な情報を隠す | 一覧では優先度を絞り、最終判断面には全根拠を保持。検索時間と誤判断を測る |
| ダッシュボード効果を一般化しない | [2026 umbrella review](https://pubmed.ncbi.nlm.nih.gov/41788668/) と [patient-safety dashboard review](https://pmc.ncbi.nlm.nih.gov/articles/PMC8496385/) | 研究は異質で、データ品質・統合・利用者評価の不足がある | 「健康改善」「安全性向上」を主張せず、合成課題の完遂・誤操作・負荷だけを報告する |
| 美観と操作性を分ける | [Tuch et al.](https://doi.org/10.1016/j.chb.2012.03.024) | 知覚評価と実作業は一致しない | VisAWI-Sと完遂率・時間・SEQ・NASA-TLXを別解析する |
| Server Component境界を小さくする | [Next.js production checklist](https://nextjs.org/docs/app/guides/production-checklist) | framework構成はドメイン安全性を証明しない | 共通殻、認証・scope及び主要集計の初期文脈はserver、変更操作と操作後の用途別再読取りはclient。個人別読取りはno-store、API認可を維持する |

## 認知・光学監査の判定

自動監査は、切れ・重なり・横あふれ・実効コントラスト・フォーカス遮蔽・target size・文字間隔・強制色・axeを検出する。これは問題が見つからなかった条件の記録であり、WCAG適合認定ではない。人間による390/1024/1920px、200%・400%、VoiceOver/NVDA、キーボードのみの確認を別のゲートにする。

30名評価は役割ごと10名、v2/v3をAB/BA各5名とする。重大誤確定0件、重大課題9/10以上、SEQ中央値5/7以上、完遂者の減少1名以内、中央値時間悪化15%以内を採用条件とする。0/30は母集団リスクがゼロという意味ではなく、比率はWilson 95%区間、対応差はbootstrap区間、二値差はexact McNemar、必要な多重比較はHolm法で示す。

## 現時点で主張しないこと

人間評価、実機読み上げ、手動拡大、実運用p75 Core Web Vitalsが完了するまで、「美しい」「使いやすい」「WCAG適合」「臨床安全性を証明」「健康・離職を改善」と一般化しない。`IDEAL_UI`の本番既定値はOFFのままとする。
