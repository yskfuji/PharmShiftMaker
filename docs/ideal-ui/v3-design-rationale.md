# 認知中心UI v3 — 設計判断・反証・検証境界

本書は、認知中心UI v3 の設計判断、その根拠及び反証、並びに現時点の検証の境界を記録する。

## 1. 結論

v3 は、v2 の配色（真珠色・深藍・青緑・抑制した琥珀色）及び自己ホストの Noto Sans JP を保ち、情報設計だけを作り直す。画面の美観は、業務成績の代理指標にしない。判断材料を同じ作業面へ残しながら、日常の入口、工程及び長期のタスクを区別する。

実装上の結論は、次のとおりである。

- 左のナビゲーション、ページ内のナビゲーション及び本文の三階層を固定し、背景・主作業面・補助面の三つを超える視覚階層を作らない。
- 計画は、同一情報の観点の切替えではないためタブにしない。計画には、番号、短い到達条件及び現在位置を持つ工程ナビゲーションを用いる。
- 申請・職員・ガバナンス・設定は、一覧と現在の状態を先に示す。新規作成・変更のフォームは、利用者が明示的に開く。
- 月間勤務表は、比較に適した意味的な表（table）を維持し、狭い画面では同じデータの日別アジェンダを用いる。
- 対象範囲（scope）、期間、公開版及び検証状態は、全画面で同じ位置に置く。公開・承認・消去・無効化では、対象・版・変更結果・通知先を、操作の直前にも示す。
- URL は列挙済みのルートだけを生成し、任意の戻り先 URL を受け取らない。権限は、画面の非表示ではなく、API で再検査する。

## 2. 根拠と反証

根拠欄の番号は、第5節の参考文献の番号に対応する。

| 判断 | 根拠 | 反証・限界 | 実装・測定 |
|---|---|---|---|
| タブと工程を分ける | デジタル庁のタブの指針［1］は、同一主題の観点の切替えと手順とを区別する | 公開サイト向けの指針であり、薬剤部の計画業務での完遂率を直接示さない | 計画は工程ナビゲーション、申請等はページ内ナビゲーションとする。利用者評価で、戻り、飛び越し及び誤公開を測る |
| 一貫した階層と言葉を使う | W3C COGA［2］及び Consistent Navigation［3］ | 一貫性だけでは、認知面のアクセシビリティや WCAG 適合を証明できない | h1、対象範囲、期間、版及び次の操作を固定の位置にし、理解の確認と VO/NVDA の評価とを別に行う |
| 表と日別表示を併設する | DADS のデータテーブル［4］及び WCAG Reflow［5］ | 代替表示が同じ意味を保つかどうかは、実データでの検証を要する | デスクトップの表とモバイルのアジェンダを同一のモデルから生成し、両端、400%及び320pxを監査する |
| 視覚的複雑性を抑える | CHI 2020 の論文［6］は、視覚的複雑性と検索・記憶との関係を報告する | 単純化しすぎると、資格・休息・版など、安全上必要な情報を隠す | 一覧では優先度を絞り、最終判断の画面には全ての根拠を保持する。検索時間及び誤判断を測る |
| ダッシュボードの効果を一般化しない | 2026年のアンブレラレビュー［7］及び患者安全ダッシュボードのレビュー［8］ | 研究は異質であり、データ品質、統合及び利用者評価が不足している | 「健康改善」「安全性向上」を主張せず、合成課題での完遂・誤操作・負荷だけを報告する |
| 美観と操作性を分ける | Tuch et al.［9］ | 知覚による評価と実作業とは一致しない | VisAWI-S と、完遂率・時間・SEQ・NASA-TLX とを別に解析する |
| Server Component の境界を小さくする | Next.js の本番チェックリスト［10］ | フレームワークの構成は、ドメイン上の安全性を証明しない | 共通シェル、認証・対象範囲及び主要集計の初期文脈はサーバーで、変更操作及び操作後の用途別の再読取りはクライアントで処理する。個人別の読取りは no-store とし、API での認可を維持する |

## 3. 認知・光学監査の判定

自動監査は、切れ、重なり、横あふれ、実効コントラスト、フォーカスの遮蔽、ターゲットサイズ、文字間隔、強制色及び axe の指摘を検出する。この結果は問題が見つからなかった条件の記録であり、WCAG 適合の認定ではない。人による390/1024/1920px、200%・400%、VoiceOver/NVDA 及びキーボードのみでの確認は、別の判定とする。

30名の評価では、役割ごとに10名とし、v2/v3 を AB 順・BA 順に各5名とする。採用条件は、重大な誤確定0件、重大課題9/10以上、SEQ の中央値5/7以上、完遂者の減少1名以内、及び所要時間の中央値の悪化15%以内とする。

0/30は、母集団でのリスクがゼロであることを意味しない。比率は Wilson の95%区間、対応のある差はブートストラップ区間、二値の差は McNemar の正確検定、必要な多重比較は Holm 法で示す。

## 4. 現時点で主張しないこと

人による評価、実機での読み上げ、手動での拡大及び実運用での p75 の Core Web Vitals が完了するまで、「美しい」「使いやすい」「WCAG適合」「臨床安全性を証明」「健康・離職を改善」と一般化しない。機能フラグ `IDEAL_UI` の本番での既定値は、無効のままとする。
