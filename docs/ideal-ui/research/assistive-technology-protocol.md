# 支援技術・拡大表示の実機評価票

本書は、VoiceOver、NVDA、ブラウザの拡大表示及び強制色を実機で確認するための、未記入の記録様式を定めます。

## 1. 位置付け

本書は、自動検査の代替ではありません。評価には、合成データだけを用います。評価者は、実施前に、端末、OS、ブラウザ、支援技術及びそれぞれの版を記録します。未実施の欄を合格として扱ってはなりません。

## 3. 共通の判定基準

評価者は、各課題を「完遂」「補助あり」「失敗」「対象外」のいずれかで記録し、発話の記録には合成の識別子だけを書きます。次のいずれかに該当する場合は、失敗とします。

- フォーカスが見えません。
- 読み上げられる名前と視覚上のラベルが異なります。
- 状態、エラー又は更新の完了が通知されません。
- 読み順が崩れます。
- 意図しない操作が行われます。
- 二次元の表と同等のリストを利用できません。

## 4. VoiceOver（macOS、Safari）及び NVDA（Windows、Firefox/Chrome）での課題

1. ログインし、本文へのスキップリンクを使います。初回の本人確認の待機中、成功後及び401の失敗時の三つの状態で、非活性な本文へフォーカスが消えないことを確認します。
2. 主要ナビゲーション、対象範囲（scope）の選択及び子画面のナビゲーションを、ランドマークと見出しだけでたどります。SPA 内で画面を移動した後、新しい画面の見出しが一度だけ通知され、入力中のフォーカスを奪わないことを確認します。
3. 月間表を表のナビゲーションで読み、職員・日付・勤務の関係が分かることを確認します。同じ情報を日別アジェンダでも選択し、勤務の詳細を読みます。
4. 欠勤、交換、休暇、紐付けの無効化、公開及び人物の消去を、確認の直前まで進めます。対象範囲、対象者、版、変更差分、取消しができないこと及び別担当による承認の必要性を、読み上げだけで識別できることを確認します。実行する場合は、専用の使い捨てのスキーマを使います。
5. 409、403、422、通信後の結果不明及び部分的な失敗を発生させます。原因と次に取れる行動とが区別されること、及び同じ冪等キーでの再送が二重の処理にならないことを確認します。
6. 入職・退職・復旧のタスクリストを行き来し、完了・未完了・自動判定・手動の証跡の違いが、色に頼らずに分かることを確認します。

## 5. 拡大・リフロー・入力

| 条件 | 期待する結果 | 結果・証跡 |
|---|---|---|
| 320 CSS px | ページ全体の横スクロールがありません。月間表は局所的なスクロール及び日別の代替を持ちます | |
| 200% | 切れ、重なり及び固定要素による遮蔽がありません | |
| 400% | 主要な操作、エラー及び確認の差分が読めます | |
| WCAG の文字間隔 | 内容・操作の欠落がありません | |
| Windows の強制色 | 状態、フォーカス、境界及び選択が識別できます | |
| キーボードのみ | 全ての操作に到達できます。ドラッグ専用の操作がありません | |
| prefers-reduced-motion | 不要なアニメーションを抑止します | |
| 横長の表の左端・右端 | 画面外の文字を誤って検出せず、実際の遮蔽は検出します | |

## 6. 完了判定

重大な誤確定、到達不能、フォーカスの消失、読み上げ不能及び内容の欠落が0件であり、かつ、未解決の問題及び未実施の条件が0件となったときに限り、支援技術の判定を合格とします。自動の axe の結果又は未記入の本様式だけでは、合格としません。
