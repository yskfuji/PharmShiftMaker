| アクセシビリティの自動評価と人による評価を併用する | [WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[W3C conformance evaluation](https://www.w3.org/WAI/WCAG22/Understanding/conformance) | 規範的な達成基準。ページ全体及びプロセス全体を評価する必要性 | 自動検査は、支援技術を用いた場合のユーザビリティを認定できない | axeに加え、キーボード、拡大・リフロー、強制色及びスクリーンリーダーによる評価を実施する |
| 自己ホストした日本語書体及び抑制した階層を用いる | [Digital Agency Design System typography](https://design.digital.go.jp/dads/foundations/typography/) | 日本の公共サービス向けのタイポグラフィーの指針 | 指針は、本製品における課題遂行成績を証明するものではない | Noto Sans JPを自己ホストし、読みやすい行の高さ及び等幅数字を維持する |
| 形成的評価の参加者数を5名より多くする | [Faulkner 2003](https://doi.org/10.3758/BF03195514) | 5名による問題発見の割合は、無作為標本間で大きく変動した | 参加者30名であっても、母集団への一般化可能性は証明できない | 役割別に参加者10名とし、不確かさ及び標本の特性を報告する |
| 実運用環境における性能を、試験環境における検査と区別して取り扱う | [Core Web Vitals](https://web.dev/articles/vitals) | LCP、INP及びCLSの、実運用環境における75パーセンタイルのしきい値 | Lighthouseは試験環境のデータであり、実運用環境のINPの代替にならない | 試験環境における目標値は維持する。ただし、性能の合格は、実運用に相当する環境における75パーセンタイルの実測値のみにより判定する |

## 結論

これらの根拠が支持するのは、選択した操作様式、依存関係への対処及び測定計画であって、画面が既に誰にとっても「美しい」又は「使いやすい」こと、法令を遵守していること、又は健康を改善することではない。v3の実装候補について、根拠に基づき述べ得る結論は、次のとおりである。

1. 設計は、合成データを用いて、役割及び失敗状態の全体にわたって試験できる。
2. 影響の大きい変更操作は、サーバーが認可し、版を管理し、冪等である。
3. 公開履歴は不変であり、個人向けの出力は本人のデータのみに限定する。
4. 本番シェルの既定画面として採用するには、所定の30名の評価、並びにアクセシビリティ及びブラウザーの全ての判定基準に合格しなければならない。

資料の版及び内容は、2026年10月2日に再確認した。本一覧においては、各資料が支持する内容と、本製品に固有の推論とを区別して示す。依存関係の検査も同日に再実行したが、その結果は一時点の観測にとどまる。本書は、法令遵守、臨床上の便益、母集団全体におけるユーザビリティ又はWCAGの認証を主張するものではない。
