# デスクトップ版の殻と起動の仕組み（M2）

本書は、デスクトップ版の殻（Electron）と、同梱の実行環境を起動する仕組みの設計を記録するものです。技術検証の結果は [m0-verification.md](m0-verification.md) に、macOS の署名の資格情報の登録手順は [macos-signing.md](macos-signing.md) に記載しています。

## 1. 位置付け

1. 本書は、設計の記録です。配布物の品質や、試行運用の安全性を保証するものではありません。
2. 本書の対象は macOS（Apple シリコン）版です。Windows 版は、保存処理の対応（M3）が済むまで起動を拒否します。

## 2. 構成

1. 殻（`desktop/main.js`）は、同梱の Python で起動役（`python -m shift_scheduler.desktop`）を1つだけ起動し、標準出力の1行ごとの JSON で進み具合を受け取ります。
2. 起動役（`src/shift_scheduler/desktop/`）は、次の順に処理します。
   - データフォルダーを用意します（所有者だけが読み書きできる権限 0700）。
   - データフォルダーの排他のロック（`state/launcher.lock`）を取ります。ほかの起動役が同じフォルダーを使っているときは、最大60秒待ってから、起動を止めて知らせます。異常終了した殻の起動役が後始末を続けている間に、アプリを開き直した場合を想定しています。
   - 導入ごとの秘密情報と、TLS の証明書を、初回だけ作ります。ただし、PostgreSQL のデータ（`pgdata/`）があるのに秘密情報のファイルが無いときは、新しい秘密情報を作らずに止めます。一部だけ復元したデータフォルダーで、既存のデータを読めなくしないためです。
   - 前回の起動役が異常終了して残した子プロセスと PostgreSQL を止めます。子プロセスは、記録した PID のうち、この実行環境のコマンドだけを止めます。
   - 同梱の PostgreSQL を初期化して起動し、業務用と独立制御用の2つのデータベースを作ります。初期化は一時フォルダー（`pgdata.new`）で行い、設定まで済んでから名前を変えます。途中で止まったときは、次回に最初からやり直します。
   - マイグレーションを適用し、独立制御を初期化して起動し、ノードを登録します。
   - API、worker、画面のサーバーを起動し、応答を確かめてから、殻に準備の完了を伝えます。
3. すべてのサーバーは `127.0.0.1` だけで待ち受けます。ポートは、画面 18513、API 18510、独立制御 18511、PostgreSQL 18512 に固定します。画面のビルドに API の場所を埋め込むためです。いずれかのポートが使用中のときは、起動を止めて知らせます。
4. 殻は、標準入力を閉じることで停止を求めます。起動の途中でも、起動役は段階の合間と待ち時間の中で停止の求めを確かめます。殻が異常終了したときも、管の終端が閉じるため、起動役はすべての子プロセスと PostgreSQL を止めます。殻は、30秒待っても起動役が終わらないときは、強制終了します。
5. 起動役は、子プロセスの終了と、PostgreSQL の停止（5秒ごとに確認）を監視します。どちらかが起きたときは、すべてを止めて殻に知らせます。
6. 起動役は、各サーバーの応答の確認で、OS の設定や環境変数のプロキシの設定を使いません。病院の端末でプロキシが設定されていても、`127.0.0.1` への確認がプロキシに送られないようにするためです。
7. 殻は、起動役の Python を `-I -B` で起動します。署名した配布物の中に、`__pycache__` を書かないためです。
8. macOS では、殻は「アプリ」と「編集」だけのメニューを置きます。コピーと貼り付け（Cmd+C、Cmd+V など）と、終了（Cmd+Q）を使えるようにするためです。再読込や開発者ツールの項目は置きません。

## 3. データの置き場所

1. データフォルダーは、macOS では `~/Library/Application Support/PharmShiftMaker` です。
2. 中身は次のとおりです。

| 場所 | 内容 |
|---|---|
| `state/secrets.json` | 導入ごとの秘密情報（DB のパスワード、署名鍵、トークンなど。権限 0600） |
| `state/children.json` | 起動中の子プロセスの PID（異常終了の後の回収に使います） |
| `state/launcher.lock` | 起動役が動いている間だけ排他のロックを取る空のファイル |
| `state/tls/` | 導入ごとの CA の証明書、サーバーの証明書と秘密鍵（権限 0600） |
| `pgdata/` | PostgreSQL のデータ |
| `storage/` | 管理対象ファイル |
| `logs/` | 各プロセスの記録（権限 0600。起動のときに 10MB を超えていれば、1世代だけ残して切り替えます。動いている間は切り替えません） |

3. 同じフォルダーには、殻（Electron）の利用者データ（Cookie、画面の保存領域など）も置かれます。Electron の既定の置き場所が、アプリの名前から同じフォルダーになるためです。上の表の名前とは重なりません。
4. アプリを削除しても、データフォルダーは残ります。消すときは、利用者がフォルダーごと削除します。バックアップと復元は、フォルダーごと、同じ時点のものを扱います。

## 4. 想定する脅威と対策

1. 対象とするのは、同じ PC のほかの OS 利用者と、同じネットワークのほかの機器です。
   - ほかの OS 利用者は、データフォルダーの権限で締め出します。
   - ほかの機器からは、`127.0.0.1` だけで待ち受けることで接続できなくします。
2. 同じ OS 利用者の権限で動くプログラム、管理者権限で動くプログラムは、対象外とします。秘密情報のファイルを追加で暗号化しないのは、このためです。
3. ほかの OS 利用者による妨害（サービス妨害）は、防ぎきれません。次のことが残ります。
   - `127.0.0.1` の各ポートには、同じ PC のほかの OS 利用者も接続できます。ログインを5回失敗させると、そのアカウントは15分ロックされるため、ほかの OS 利用者が利用者を締め出し続けることができます。
   - 固定のポートを先に使われると、起動できません。
   - どちらの場合も、秘密情報やデータは渡りません（TLS の証明書の固定と、SCRAM による認証で守ります）。試行は、OS 利用者を限った PC で行う前提です。
4. 殻は、次の対策を行います。
   - TLS は、導入ごとの CA の公開鍵でサーバーの証明書の署名を自ら確かめ、主体の別名（SAN）が `127.0.0.1` のものだけを受け入れます。CA の秘密鍵は発行後に破棄しています。
   - 画面の移動（転送、フレーム内の移動を含みます）の先を `https://127.0.0.1:18513` に限り、新しいウィンドウ、webview、カメラなどの権限の要求を拒否します。スペルチェックの辞書の取得も止めます。
   - 初期設定の要求（`/api/setup/bootstrap`）にだけ、初期設定のトークンを付けます。このトークンは起動のたびに作り直し、保存しません。起動役は、アカウントが1件もないときにだけ、殻にトークンを渡します。
   - Electron の fuse で、Node としての実行、`NODE_OPTIONS`、デバッガーの引数を無効にし、asar の完全性の検査と Cookie の暗号化を有効にします。
5. 子プロセスには、必要な環境変数だけを渡します。殻の環境変数は、OS と実行環境に要る少数のものを除いて引き継ぎません。
6. PostgreSQL は、次のように構成します。
   - 業務用と独立制御用のデータベースは、それぞれ専用の一般のロール（superuser ではありません）が所有し、所有者だけが接続できます（`pg_hba.conf`）。superuser は、起動役がロールとデータベースを管理するときだけ使います。
   - すべての接続で、SCRAM による認証を必須にします（`require_auth=scram-sha-256`）。PostgreSQL が止まっている間に、ほかの OS 利用者がポートを取っても、パスワードは渡りません。
   - エラーの記録には、SQL 文と詳細の行（値を含みうるもの）を書きません。ただし、エラーの主な文（例：型の変換の失敗）には入力の値が入る種類があるため、PostgreSQL の記録に個人情報が残る可能性はなくなりません。記録は、権限 0600 のファイルに置きます。
   - PostgreSQL の管理用のプログラム（initdb、pg_ctl）には、superuser のパスワードを環境変数で渡しません。

## 5. 配布物の作り方

1. `desktop/scripts/assemble-runtime.sh` が、PostgreSQL、Python、Node.js をダウンロードし、固定した SHA-256 と照合してから展開します。Python には `requirements.lock` の依存をハッシュ付きで入れ、製品のコードを加えます。画面は standalone で出力します。
2. electron-builder が `.app`、dmg、zip を作ります。
   - 署名の資格情報がないとき（PR の検証）は、アドホック署名とし、hardened runtime を外します。アドホック署名では、ライブラリの検証で起動できないためです。
   - 正式の配布では、Developer ID で署名し、hardened runtime を有効にして、公証を受けます。来歴の証明（Artifact attestations）も付けます。この手順は、所有者の承認を経て動く environment「desktop-release」で行います。殻のビルドの道具（npm の依存）は、署名の資格情報を読み込む前の手順で入れます。依存のパッケージの導入時のスクリプトが、資格情報を読めないようにするためです。
3. 現在の容量は、`.app` で約 950MB です（Python と依存 約 290MB、PostgreSQL 約 150MB、Node.js 約 140MB、画面 約 60MB、Electron 本体）。

## 6. 確かめたこと（2026年11月24日、手元の macOS、合成データ）

1. 起動役の試験（`desktop/scripts/smoke.py`）で、次のことを確かめました。
   - 空のデータフォルダーから起動し、ログイン画面が応答すること。
   - 初期設定は、トークンがないと 403 で拒否され、トークンがあると成功すること。
   - 作った管理者でログインでき、Cookie に Secure と HttpOnly が付くこと。
   - 待ち受けが `127.0.0.1` だけであること。
   - 停止の後にポートが解放され、2回目の起動でアカウントが残っていること。
2. 殻の試験で、次のことを確かめました。画面写真は、開発の担当が目で確かめました。
   - 初期設定の済んだデータで、ログイン画面が表示されること。
   - 空のデータで、初期設定の画面が表示されること。
3. 独立レビューの指摘に対して、次のことを確かめました。
   - 業務用のロールは独立制御用のデータベースに接続できず、その逆もできないこと。業務用のロールが superuser でないこと。
   - 起動の途中（マイグレーションの段階）で停止を求めると、0.3秒で止まり、ポートが解放されること。
   - 起動役を強制終了（SIGKILL）した後の起動で、残った子プロセスと PostgreSQL を回収して起動できること。
   - 殻が初期設定の要求にトークンを付け、初期設定が成功すること。初期設定の後の起動では、トークンを渡さず、ログイン画面を表示すること。
4. 確かめる中で、次の不具合を見つけて直しました。
   - 初期設定の画面で、セッションの更新と本人の確認が動き、ログイン画面との間で往復し、画面が表示されませんでした。`/setup` を、セッションのない画面として扱うようにしました。
   - 殻が、画面の描画が止まったときに終了しませんでした。起動役が止まった後は、画面を待たずに終了するようにしました。

5. 2回目の独立レビュー（2026年11月25日）の指摘に対して、手元の macOS で、合成データを使って次のことを確かめました。
   - プロキシの環境変数に存在しない宛先を入れた状態でも、起動役の試験がすべて成功すること。待ち受けが `127.0.0.1` だけであること（空の結果を合格としない確認に改めました）。実行環境の中に `__pycache__` が1つも作られないこと。
   - 動いている起動役と同じデータフォルダーで2つ目の起動役を動かすと、2つ目は約60秒待ってから「使用中」として止まり、1つ目は動き続けて画面も応答すること。
   - `secrets.json` を外して起動すると、新しい秘密情報を作らずに止まること。
6. 確かめる中で、次の不具合を見つけて直しました（前から残っていたものです）。
   - 起動役がエラーで終わるとき、標準入力を読むスレッドと終了処理がぶつかり、SIGABRT で落ちていました。後始末を終えた後に、終了処理を飛ばして終わるようにしました。

## 7. 確かめていないこと・残っていること

1. 署名、公証、Gatekeeper の評価は、資格情報の登録の後に確かめます。
2. macOS のメニューで、コピーと貼り付け、Cmd+Q が効くことは、実際のキー操作ではまだ確かめていません。
3. アドホック署名の配布物を作り直すと、署名が変わるため、macOS が Cookie の暗号化の鍵（キーチェーンの「PharmShiftMaker Safe Storage」）の使用の許可を求めます。画面がロックされていると応答できず、画面の読込みが止まります。Developer ID で署名した配布物では、版を上げても署名の主体が変わらないため、この問題は起きない見込みです（未確認）。
4. 同梱する PostgreSQL、Python、Node.js、Electron の許諾表示を、配布物と `THIRD_PARTY_NOTICES.md` に加える作業が残っています。
5. バックアップと復元の操作は、画面からはまだ行えません。
6. PostgreSQL のメジャー版を上げるときのデータの移行は、まだ設計していません。
7. Intel の Mac には対応していません。
8. Windows 版は、M3 の保存処理の対応の後に、同じ試験を行います。
9. 2回目の独立レビューの指摘のうち、次のものは直さずに残しています（いずれも重大度は低）。
   - 電源断の後に `postmaster.pid` の PID がほかのプロセスに再利用されていると、`pg_ctl` がそのプロセスに停止の信号を送るおそれがあります。
   - 異常終了の後の回収は、実行環境のパスで自分の子プロセスを見分けます。アプリを移動した後などでパスが変わると、残った子プロセスを回収できず、ポートが使用中で起動できないことがあります。
   - 前回の子プロセスの回収（1件あたり最大10秒）の途中では、停止の求めを確かめません。
   - 試験用の環境変数（`PSM_SMOKE_RESULT` など）が、正式の配布物でも有効です。
   - Web 版（サーバー配備）でも、`/setup` はログインなしで表示されます。初期設定の要求そのものは、デスクトップ版以外では 404 で拒否します。
   - Electron の fuse の `grantFileProtocolExtraPrivileges` を無効にしていません。
