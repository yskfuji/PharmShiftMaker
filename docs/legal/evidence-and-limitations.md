# 公開・法務・運用文書の根拠と限界

本書は、公開に当たって行った判断の根拠と、その根拠からは結論できない事項とを区別して示す。

## 1. 基本的な考え方

1. 法令への適合は統計的な仮説ではなく、適用される法令等、契約、対象となる情報及び運用の実態に基づく判断である。テストの成功率又はコードカバレッジから推定しない。
2. 根拠資料の版及び掲載状況は、2026年10月4日に各公表機関の公式ページで確認した。公開後も改訂の有無を確認し、導入時点の最新版を用いる必要がある。

## 2. 判断と根拠

| 判断 | 根拠 | 採用した内容 | 反証・限界 |
|---|---|---|---|
| 独自部分の権利を著作権者が単独で保有し、利用には事前の書面による許諾を要するものとする（2026年10月25日に MIT License から変更） | [GitHub「Licensing a repository」](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)、[SPDX MIT](https://spdx.org/licenses/MIT) | 権利者、対象年及び利用条件を `LICENSE` に記載する。変更前に MIT License の下で取得された複製の権利が遡って消滅しないことを明記する | 公開した後の複製及び fork は回収できない。免責の条項は、強行法規上の義務を消滅させない |
| 導入施設の責務を別の文書にする | [個人情報保護委員会・通則編](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/) | 利用目的、安全管理措置、従業者・委託先の監督、本人への対応、保存及び消去を、導入施設が定める | 汎用の文書だけでは、個別の事業者又は医療機関の適法性を確認することはできない |
| 全ての勤務形態について法令への適合を自動判定するとは表示しない | [厚生労働省「いわゆる『シフト制』について」](https://www.mhlw.go.jp/stf/newpage_22954.html) | 勤務案を候補と位置付け、契約、就業規則、労使協定等との照合を求める | 同資料の「シフト制」の定義は固定的な三交替勤務等を除くため、病院の全ての勤務形態へは一般化できない |
| 医療情報を扱う構成は別途確認する | [厚生労働省「医療情報システムの安全管理に関するガイドライン 第7.0版」](https://www.mhlw.go.jp/stf/shingi/0000516275_00006.html) | 患者情報を既定では扱わない。扱う場合は、導入施設が適用範囲及び追加の措置を確認する | 職員の勤務を扱う合成環境をテストしただけでは、医療情報システムとしての適合を認定することはできない |
| CI で使う外部の action を完全なコミット SHA に固定する | [GitHub「Secure use reference」](https://docs.github.com/en/actions/reference/security/secure-use) | action を検証時点の完全な SHA に固定し、権限をジョブごとに限定する | SHA の固定は、固定先のコード又はワークフローの設定誤りを無害にするものではない。更新の監視が必要である |
| `main` を pull request と必須の検査で保護する | [GitHub「About protected branches」](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) | 必須のステータスチェック、会話の解決、force-push 及び削除の禁止を設定する | 単独で管理しているため、必須の承認者数を1以上にすると、所有者自身が更新できなくなる場合がある。そのため、必須の承認者数は設定していない |
| セキュリティのテストの観点を体系化する | [OWASP ASVS 5.0](https://github.com/OWASP/ASVS) | 認可、入力、セッション、ファイル、ログ等の反証のテストに利用する | チェックリストへの対応又は自動検査での検出0件は、安全性の証明ではない |

## 3. 結論

1. 公開に必要な事項は、次のとおりである。\
   （1）選択した権利表示及び利用条件と、実装との整合\
   （2）機微な情報、実在の人物のデータ及び巨大な生成物の除外\
   （3）再現できる検証\
   （4）既知の限界の明示\
   （5）GitHub 上での継続的な保護
2. これらを満たしても、導入先に固有の法令への適合、業務上の妥当性、使いやすさ又は安全性が自動的に成立するわけではない。
